# 웹 도구 사용 가이드

## 처음 실행

설치 후 `scripts/start.ps1`로 서버를 실행하고 `http://127.0.0.1:8000`을 연다. 기본 입력은 원본 Excel의 66지역과 분석으로 생성한 경기 후보 10개이다. 값이 계산되기 전의 KPI는 미계산 상태다. **최적화 실행**으로 결과를 얻는다. 비용은 원/일이며, 여러 기간의 누적 목적값은 기간별 일평균 KPI와 구분한다.

## 지도와 거점

- 원은 고정 수요지역, 프리미엄 원은 수요 규모를 나타낸다. 클릭하면 상품별 수요와 좌표를 볼 수 있다.
- 번호 마커는 DC 후보다. 개설 여부는 결과의 마커 색으로 구분한다. 마커 또는 왼쪽 목록을 선택하면 편집할 DC가 바뀐다.
- **지도에서 DC 추가**를 누르고 지도를 클릭한다. 추가 후 후보 이름·임대료·처리비·용량을 설정한다.
- 마커를 드래그하거나 **DC 위도/경도** 숫자를 수정한다. 수정 시 결과가 초기화되므로 다시 실행하면 새 거리행렬로 계산한다.
- 거점 운영 허용을 해제하면 그 후보는 개설할 수 없다. 삭제하면 해당 거점을 참조한 제약도 함께 제거한다. 마지막 후보는 삭제할 수 없다.
- 지도 레이어 설정에서 수요/프리미엄/DC/연결선을 켜거나 끈다. 전체 네트워크 보기로 범위를 맞춘다.

Haversine 원과 연결선은 직선거리 표시이며 실제 도로 서비스 권역을 보장하지 않는다. 사용자 추가·이동점의 경기 소재 여부, 임대·인허가 적합성은 별도로 확인해야 한다.

## 정책·차량·설정

왼쪽 **정책** 탭에서 12종 템플릿을 선택해 제약을 추가한다. 각 제약은 활성화, 값 수정, 대상 지정, 기본값 복원, 삭제가 가능하다. 실행 결과의 적용 표시로 모델 반영 여부를 확인한다. 비활성 제약은 다음 실행에서 제외된다.

| 정책 | 단위 / 해석 |
|---|---|
| 최소/최대 DC 수 | 개설 DC 수; 후보 수 자체를 제한하지 않음 |
| 처리용량 | CBM/일. 빈 값이면 DC별 입력용량, 숫자면 공통 또는 지정 DC 상한 |
| 최대 배송거리 | 모든 상품에 적용하는 편도 km |
| 프리미엄 거리 | 프리미엄 상품에만 적용하는 편도 km; 기본 30 |
| 강제/금지 개설 | 지정 DC |
| 배정 허용/금지 | 지정 지역–DC 조합. 허용 여러 개는 해당 지역의 허용 목록 |
| 최대 회차 | 차종 또는 전체 차종 합계의 회/일 |
| 최소 충족률 | 0~1, 상품 개수 기준, 매 기간 적용 |
| 예산 | 기간별 일평균 총비용의 원 한도 |

**차량** 탭에서 차종의 활성 상태, 정수 CBM 용량, 회당 고정비, km 단가, 일별 최대 회차를 수정한다. 최대 회차의 빈 칸은 제한 없음이다. 차량 대수·근무시간 배정과는 다르다.

**설정** 탭은 수요 배수, 비용 가중치, 패널티, 공급비, 미충족 허용, 프리미엄 분리, 계획기간, 제한시간과 gap을 제공한다. 슬라이더는 다음 최적화의 입력을 바꾸며 현재 해의 결정변수를 직접 움직이지 않는다. 미충족 허용 시 비용과 패널티의 비교에 따른 **경제적 미충족도 가능**하다. 이는 [가정 A11](assumptions.md)을 따른다.

3년 성장 설정은 전역 수요 배수를 1로 하고 기간별 1.2/1.44/1.728배와 매년 365일을 설정한다. DC 개설은 기간 전체에 공유한다. Base 1일을 선택한 뒤에도 전역 수요 배수는 별도 필드이므로 확인한다.

## 결과 읽기

상단 KPI와 결과 패널에서 비용 분해·충족률·거리·회차를 확인한다. 배정표에는 상품별 출고와 미충족, DC별 표에는 처리량과 물량 비중, 차량 표에는 일반/프리미엄 운행과 적재량이 나온다. 평균거리는 출고 CBM 가중 편도, 총거리는 회차 가중 왕복이다.

- `optimal`: 설정한 후보·모형에서 Solver의 허용 gap 기준을 만족했다. gap 0과 양수는 구분한다.
- `feasible_limit`: 실행가능성을 검산한 시간제한 해. 최적성은 미증명이다.
- `infeasible`: 활성 제약을 동시에 만족하는 해가 없다. 메시지는 원인 추정이며 IIS 증명이 아니다.
- `no_solution`: 제한시간 안에 실행가능한 정수해를 얻지 못했다.
- `error`: 잘못된 입력, Solver 오류 또는 결과 검산 실패. 결과를 의사결정에 사용하지 않는다.

전량 충족을 요구하면 현재 후보의 프리미엄 권역 때문에 infeasible일 수 있다. 단순히 Solver 시간을 늘리기보다 후보 위치·거리 정책·제약 충돌을 확인한다.

## 저장·비교·업로드

시나리오 이름을 정하고 저장하면 입력과 계산 당시 결과가 브라우저에 보존된다. 복제한 시나리오를 수정·재실행하여 비교한다. 서로 다른 기간의 누적 총비용을 같은 일비용처럼 비교하지 않는다. 브라우저 저장공간이 제한될 수 있으므로 JSON으로 백업한다. 다른 브라우저/PC로 자동 공유되지는 않는다.

Excel 업로드는 원본과 같은 수요 구조 또는 [지원 헤더](data-format.md)를 사용한다. 검증 실패 시 누락·행 번호 등의 오류를 확인한다. 업로드한 데이터는 기존 프로젝트 원본을 덮어쓰지 않는다. 정상 결과는 Excel로 내보낼 수 있다. JSON 가져오기는 서버 스키마 검증 후 반영한다.

분석에 대한 권고와 수치 근거는 [정책 보고서](policy-recommendations.md), 재현 파일은 `artifacts/analysis/` 및 `artifacts/growth-capacity/`에 있다.
