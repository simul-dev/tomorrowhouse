# 완료 내역

## 구현 범위

제공된 PDF 11쪽과 Excel 66지역을 직접 분석해 문제·가정·문헌·방법론·수식을 정리하고, UI 독립 Python 최적화 엔진과 실제 실행 가능한 React GIS 웹 앱을 구현했다. 원본 파일 해시와 기존 Git 커밋을 보존했다. 단계별 변경을 로컬 커밋했으며 원격 push·외부 배포·PPT 생성은 하지 않았다.

앱은 OSM 지도에서 후보 추가·선택·이동·삭제, DC 비용·용량·허용 상태, 고정 수요 조회, 12종 제약 편집과 복원, 차량·수요·비용·계산 파라미터, 15개 KPI, 배정·DC·회차 표, 비용 차트, 저장·복제·비교, JSON 백업 및 Excel 업로드·결과 다운로드를 제공한다.

## 채택 방법

문제는 시설입지·단일 DC 배정·다상품·이종 차종의 직배송 회차 통합 문제이다. 초기 경기 후보 10개는 가중 탐욕 입지 휴리스틱, 개설·배정·정수출고·정수회차는 MILP로 결정한다. 독립 구간은 정확한 동적계획으로 축약하고 결합 자원제약에는 전체 MILP를 사용한다. Solver는 SciPy/HiGHS의 branch-and-cut이며 거리모형은 Haversine이다. 3년에는 개설만 공유하고 운영 결정을 기간별로 둔다.

## 결과·검증

- Base: 구리·수원·부천·용인 4DC, **541,155,890.88원/일**, 충족률 **99.406%**, 476회/일, gap 0.
- 경제적 미충족 허용 가정 아래 총 161개 미충족(대형4/프리미엄157). 일반 배송에 프리미엄 거리 상한을 자동 적용하지 않는다.
- 용량 비활성 3년 통합: 의정부를 추가한 5DC, 누적 **805,635,003,933.06원**, gap 0.
- Python **67개**, Chromium 주요 흐름 **10개**, 저장 입력·결과 **28쌍** 검산 통과. 프로덕션 빌드 성공.
- 용량 제약의 일부 해는 시간제한 incumbent이며 해당 gap과 운영·서비스 해석을 [정책 보고서](policy-recommendations.md)에 명시했다.

검증 중 발견한 오류와 수정, 의존성 경고는 [검증 기록](validation.md)에 보존했다. 실행과 설치는 [README](../README.md), 조작법은 [사용 가이드](user-guide.md)를 따른다.

## 남은 한계와 다음 우선순위

직선거리·행정 대표점·후보 생성 휴리스틱을 사용하고, 실제 경기 부지 적합성·도로시간·도서 접근성·차량 근무시간·3차원 적재·재고·불확실성은 검증하지 않는다. 공급비와 패널티의 개당 단위, 경제적 미충족 허용은 명시적 가정이며 운영 정책과 맞추어야 한다. 브라우저 저장은 로컬이며 인증·DB·작업 큐 기반의 다중사용자 서비스는 범위에 없다.

다음 순서는 ① 실제 부지·도로거리·SLA 데이터 확보, ② 미충족 정책과 공급비 단위 확정, ③ 실측 DC·차량 한도와 장시간 용량모형 계산, ④ 수요 변동·장애 모사 검증, ⑤ 운영용 저장·작업 관리 확장이다.
